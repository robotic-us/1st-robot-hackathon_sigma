# CLAUDE.md

SIGMA — an infant-responsive robotic cradle (research prototype, Robot
Hackathon 2026, KAIST). The motion behaviour is a transcription of
`docs/infant_robotic_cradle_evidence_report_ko.pdf` (Korean): a 50-motion
library (M01–M50), a kinematic envelope, and a safety-first state machine.
That PDF is the spec — when motion behaviour is in question, it wins.
Architecture and the report↔code traceability table: `docs/ARCHITECTURE.md`.

Brains: `reflex` (local algorithm), `ollama` (local LLM, `OLLAMA_URL`/`OLLAMA_MODEL`/`--llm-model`), `claude` (paid Anthropic API). The dashboard switches brains live (`/policy`) and retunes the temperament live (`/taste`); every brain fails safe to the report ladder. serve.py runs the demo rhythm `--pace 10` by default — each motion plays ~10 s before the machine re-decides; `--pace 30` restores the report's own cadence (CradleMachine default). |

## Layout

- `serve.py` — the entry point: sensing → CradleMachine → MotionEngine → SSE/MJPEG dashboard (`web/`: `index.html` markup + `style.css` + `app.js`, no build step). Card-based clinical-monitor UI: "now" cards, the emotion-process timeline (seeded from `/history`, 1 Hz × 15 min), decision feed + learned preferences (when `--policy`), camera/controls/log, library + internals drawers. 2D only; 3D lives in RViz.
- `core/` — `cradle.py` (M01–M50 library + MotionEngine + CradleMachine — the heart), `policy.py` (the IDEA.md soothing policy: happiness ranks, ReflexBrain/ClaudeBrain, `SoothePolicy` — wired in as `CradleMachine.advisor`, which only ever *suggests* the P1 motion a trial uses; the machine validates every pick and keeps all safety decisions), `pvector.py` (P-Vector world model; the m50 suite round-trips the compiled CSVs through it), `phorce_iface.py` (only file that knows phorce/ROS 2; also `SlotBridge`, the decisions→slots replayer).
- `perception/` — `watch.py` (**the baby recognizer**: the teammate's five-state MVP from `docs/example.py` *plus* the report-spec layer — `AudioTrack` §4.2 duty/ΔL/unit features, `BodyMotion` whole-frame flow, `InfantJudge` §4.3/§5 sleep ladder + fuss/cry/pain states. FER+ is the learned §4.1 label source; a signal a sensor can't supply is `None` and its judgments never fire), `sense.py` + `listen.py` (visual channel + audio → distress; watcher-first, FER+ fallback), `face/` (YuNet/SFace/FER+ package).
- `apps/` — `animate.py` (RViz player: `--tour`/`--motion` replay the library through `MotionEngine`).
- `core/rig.py` — **the measured five-bar kinematics + RosSide**; the one home of the geometry convention (was `apps/demo.py`).
- `webapp/` — the dashboard as a Next.js app, a *client* of `serve.py` and not a replacement: the `web/` trio is still what the server serves and what `tests.py` checks. Needs a Node toolchain this repo does not ship; see `webapp/README.md`.
- `tools/` — one-off generators: `make_motions.py`, `make_urdf.py`, `fetch_models.py`.
- Data: `motions_m50/` (the 50-slot library), `models/` (ONNX, gitignored), `cad/`, `faces/` (biometric, gitignored), `bench/` (licensed infant photos for VERIFY.md layer 3). *(Legacy removed 2026-08: `motions/`, `tags/`, `slots.json`, `perception/tag.py`, `core/dream.py`, `core/slot_table.py`, `apps/{demo,care,run}.py`, `tools/enroll.py`, `--dream-auto`, `/slots`, `/play` — the DREAM/tag stack. `core/pvector.py` stays: the m50 suite round-trips the compiled CSVs through it.)*

## Conventions

- **Run everything from the repo root** — data paths (`motions_m50/`, `cad/`, `web/`) resolve from cwd. Scripts in subdirs still run directly thanks to a `sys.path` bootstrap block at the top of each.
- **Tests live only in `tests.py`** — modules carry no selftests and no `--selftest` flags. New behaviour → new/extended suite there, registered in `SUITES`.
- Time is injected everywhere in `core/cradle.py` (no `time.time()` inside) so the machine is testable with a fake clock. Keep it that way.
- Module docstrings follow a house style: what it is, why it exists, run lines. Match it.

## Hard-won facts (do not rediscover)

- **OpenCV is 4.5.4** on this Jetson → YuNet must stay the 2022mar model (2023 head won't parse). `tools/fetch_models.py` pins commit + SHA-256.
- **pcm MotionMap rules**: MS ID inside the CSV must match the filename number; `MD ID` is 1-based; P-Vector cell = `"yd_deg, L_traj_ms(1 kHz), s0, sd"` with `yd` an *absolute* target in degrees; slot ids capped at `MAX_MOTION_ID = 50`.
- **Lever arm**: `PIVOT[2] - AXIS0[2]` (≈227 mm) → 1° ≈ 4 mm of sway is the *aggregate* gain, and it is still the right number for a back-of-envelope check. It is not a per-crank conversion — see the five-bar facts below. Constants live in `core/rig.py`, printed by `make_urdf.py` on every rebuild.
- **R-grade motions** (M29–M50) are research-only: engine refuses them without `--research`; never route them into automatic behaviour.
- **The N system (N01–N34, grade N)** lives beside the report library in `core/cradle.py` (`N_LIBRARY`, kind `npath`, shapes in the ML–Z plane, envelope-gated at import like everything else). It is the policy's whole search space (`N_CANDIDATES`, 26 sustained entries — no N01, no decay variants); the baby's `Personality` has *feature-level* tastes (shape/size/speed/vibe + mood interplay) on top of id-level love/hate, and `ReflexBrain` generalises over the same features and never lets one motion monopolise a fussing baby (`MAX_RUN`).
- **The rig is two five-bar linkages, not a parallelogram rocker.** Measured off `docs/udrf_assembly.stl` (contact graph + IK), not assumed. Every leg is a *two-link chain* — `axis_N` → `lower_N` (crank, 152 mm) → knee → `upper_N` (rod, 152 mm) → platform — and all four legs are the same part. Legs 0 and 1 share one base pivot and meet at **one** platform point with mirrored elbows (+35.6°/−47.0°); legs 2 and 3 likewise. Two cranks, two rods, one shared endpoint = a closed five-bar, 2 DOF per pair. The passive knee absorbs the reach change a rigid parallelogram could not.
- **Three channels, and Z is real.** `sway` (all four cranks the same way) → horizontal, **4.17 mm/deg**. `heave` (each pair's two cranks *opposed*) → **vertical, 3.02 mm/deg**. `pitch` (pair against pair) → see-saw. Cross-checked: sway A10 solves to 2.40° against the report's documented 2.53°. The old "Z modes can't play / no vertical DOF" claim was wrong — M48–M50 now compile to real motion.
- **The assembly STL is not finished, so do not read the rest pose off it.** The top four bearings are not yet mated to the table: the platform is only resting in place, the two pairs sit at unequal reach (228.3 vs 262.0 mm) and the table is tilted 9.7° — confirmed twice over, by its deck normal `(-0.17, 0, 0.99)` and by the line through its mounts. Taking `REST_A`/`REST_B` from the export baked that tilt into every motion. What the export *does* pin down (because it does not depend on the arms) is that the table is rigid with coplanar mounts 200.4/199.6 mm apart, matching the 200.0 mm base-pivot separation — so the neutral pose is the symmetric one: equal reach, each endpoint above its own base, table level, cranks at ±36.43°. `RIDE_MM = 245.2` (the mean of the two observed reaches) sets where in the travel that sits and is **the one number still worth measuring on the finished rig**.
- **AP does not exist as a translation.** Every joint turns about Y, so all motion is in the XZ plane; there is no second horizontal axis. The report's 11 AP entries are rendered as **pitch** (`AP_AS_PITCH` in `core/rig.py`) — a deliberate substitution, not the report's motion.
- **`core/rig.py::axis_angles()` / `cradle_angles()` is the one definition.** It solves the real five-bar IK (reproduces the CAD's own crank angles to 0.6°). The compiler, `serve.py`'s RViz mirror and `apps/animate.py` all go through it; `tests.py::m50` and `::animate` assert both the CSVs and the live path. Fixing only one of the three silently collapses everything back into the same sway — that has now happened twice.
- **The linkage is nonlinear, so bounds need both directions.** At the level neutral the two pairs are identical and 10 mm of sway costs [2.27, 2.40, 2.27, 2.40]° — but the cranks still differ within a pair, −20 mm costs more crank angle than +20 mm, and pitch/heave cost more per millimetre than sway (3.02 vs 4.17 mm/deg). Any ceiling computed from sway alone, or from one sign, under-counts; `tests.py::animate` derives its ceiling over every channel and both signs for exactly this reason.
- **Every upper arm joins the holder; the tree is re-rooted to make that true.** A URDF is a tree, so the holder can have only one parent — but all four arms carry it in hardware, and a model where three join nothing is not the machine. Leg 0 runs *up* to the holder and legs 1–3 hang *down* from it: `base_link → axis_0 → lower_0 → upper_0 → platform → upper_{1,2,3} → lower_{1,2,3} → axis_{1,2,3}`. The knees are real joints too (`joint_knee_N`), not welds. The open end is therefore at the actuators — and they are bolted down, so **closure means each actuator lands back on its own pivot**: `tests.py::animate` walks the published joints through the real URDF exactly as `robot_state_publisher` does and asserts this (worst 0.025 mm across all channels).
- **`joint_state()`'s first four entries are NOT the four cranks.** The order is `axis_0, knee_0, platform, bearing_1, knee_1, bearing_2, knee_2, bearing_3, knee_3` — it interleaves, because each leg hangs off a different parent. Use `cradle_cranks()` for anything measuring amplitude; `library_angles(..., solve=)` picks which. Indexing `[:4]` for "the cranks" is wrong and reads as a wildly wrong amplitude. **`core/rig.py::JOINT_NAMES` is the only joint-name list** — both publishers (`RosSide`, `apps/animate.py`) reference it, never a copy; a stale copy is how RViz broke after the re-root (nonexistent `joint_axis_1/2/3` published, real `joint_bearing_1/2/3` never published, three arms with no TF). `tests.py::animate` asserts the list matches the URDF's revolute joints and that both publishers share the one object.
- **Angles are measured from +Z toward +X, everywhere, via `_ang()`.** Writing the holder's tilt the natural way (`atan2(Δz, Δx)`, from +X) flips its sign against the joint convention — the holder then rotates the wrong way and *doubles* its tilt instead of levelling, which put the far actuators 68 mm off their pivots. One convention or nothing lines up.
- **Solve each leg against its own mount, with its own link lengths.** The holder's four mounts sit a few mm apart, and the legs measure 151.7–152.5 (crank) / 151.9–153.4 (rod). Treating each pair as sharing one endpoint, or using one rounded length for all four, each cost about a millimetre of closure error.
- **`--viz-gain` multiplies plate travel, not joint angles.** The linkage is nonlinear, so scaling the angles produces a pose the mechanism cannot reach and lifts the rods off their bearings. `cradle_joint_state(..., gain=)` scales the travel and re-solves, so the exaggerated pose is a real pose. At gain 5 the worst joint reaches 39.6°, well inside the ±90° limit.
- **`./sim.sh` does not move anything.** The phorce sim backend announces itself in `/tmp/sigma-sim.log` as a `mechanism-neutral fake PCM ... 로봇은 움직이지 않습니다 (aggregate 실행 800ms)`: it validates MS IDs, request tokens and completion semantics, then returns SUCCEEDED after a fixed ~0.8 s without walking the P-Vector chain. Measured — a 9-segment slot and a 128-segment 120 s taper both take 0.78 s, and `pvector_index` never leaves 255. Never use it to judge a trajectory; use RViz (`cad/view.sh` + `apps/animate.py --tour`).
- **The watcher's motion plan maps onto the report's machine, not around it.** `perception/watch.py::distress_of` puts a visual-only DISTRESS_FACE in the fuss band ([0.30, 0.42] < CRY_LEVEL 0.45), so GENTLE_TEST_ONLY = the machine's own M10 trial, and the ladder — which only climbs at `ema >= CRY_LEVEL` — stays closed until the microphone's cry-band fuses in. That is the spec's "audio required before escalating" enforced by thresholds, not by a new code path. UNKNOWN maps to `present=False` (the safety gate), never to a distress level. Don't give the watcher its own motion commands.
- **Report-spec judge rules (sections 4.2–5)**: cry is decided by **duty cycle + vocal-unit length**, never loudness alone (§4.2's own warning); a closure <1 s is a blink; closure within 2 s of a vocalisation is never sleep; SLEEP_TENTATIVE = 10 s closed+quiet, SLEEP_STABLE adds 60 s low body flow; improving/worsening = 2 of the *observable* signals over 30 s. `CRY` maps ≥ CRY_LEVEL because audio confirmed it. Pain/posture → `Reading.alarm`, which rides the machine's fault input (same path as a jam) — interrupt and call, never soothe.
- **Posture (report §1.1) is coarse relative cues, deliberately.** BlazePose (`models/pose_estimation_mediapipe_2023mar.onnx`, verified to parse *and run* under cv2 4.5.4 before pinning) supplies shoulders; `PostureTrack` raises risk only on sustained (≥2 s) head roll ≥60°, shoulder-visibility asymmetry, or shoulder-width collapse — because BlazePose/FER+ are adult-trained and absolute keypoints on an infant are unvalidated. No baby is available to test on: the verification protocol is `docs/VERIFY.md` (synthetic streams → virtual-baby closed loop → doll/photo bench table → `--video` replay regression). Keep every new recognizer claim verifiable through those layers.
- **Policy credit is engagement-gated** (`core/policy.py::SoothePolicy.observe`): a step's outcome is the rank last seen while its motion played at strength (env > 0.2, not tapering), settled when the engine parks. Crediting the *best* rank while merely `engine.active` let natural recovery during tapers and ramps credit the motion — the first learn_report run had the policy exploiting a motion the baby hated. `tests.py::policy` asserts hated motions never score positive.
- The safety gate (jam or face/tag lost >0.7 s → taper to zero in 5 s + caregiver alert) runs even when auto mode is off. Don't weaken it.
